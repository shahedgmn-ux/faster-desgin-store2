# Faster Desgin — فروشگاه فایل‌های دیجیتال

نسخه ۱.۶ رابط فروشگاه با تم مشکی/سبز فسفری، رابط فارسی و RTL، ترنزیشن‌ها و داشبورد مدیریتی نمایشی.

## اجرا در ویندوز
1. Node.js نسخه LTS را نصب کن.
2. این پوشه را استخراج کن.
3. در پوشه پروژه نوار آدرس File Explorer را انتخاب کن، `cmd` بنویس و Enter بزن.
4. اجرا کن:

```bash
npm install
npm run dev
```

## پنل مدیریت پیش‌نمایش
از دکمه «مدیریت» بالای سایت وارد شو. نام کاربری مدیر اصلی `admin` و رمز نمایشی `2468` است.

امکانات نسخه ۱.۴:
- افزودن تصویر یا ویدئوی پیش‌نمایش به هر محصول (حداکثر ۲ مگابایت برای هر فایل)؛ پیش‌نمایش در کارت محصول و پنجره جزئیات نمایش داده می‌شود.
- سفارش پس از ثبت در وضعیت «در انتظار تأیید مدیر» می‌ماند؛ مدیر می‌تواند آن را تأیید و دسترسی آزمایشی کتابخانه را فعال کند یا رد کند.
- ساخت حساب مدیر جدید با نام کاربری و رمز اختصاصی و انتخاب دسترسی‌ها برای محصولات، سفارش‌ها، مشتریان، تنظیمات و اطلاعیه‌ها. فقط مدیر اصلی می‌تواند حساب مدیر بسازد.
- دکمه شناور باز/بسته‌کردن سایت پس از ورود مدیر؛ هنگام بسته‌شدن صفحه نگهداری نمایش داده می‌شود. اگر سایت بسته باشد، دکمه شناور «ورود مدیر برای بازگشایی» نیز در دسترس است.
- داشبورد آمار، افزودن/حذف محصول، ویرایش عنوان و قیمت، مشتریان، اطلاعیه‌ها و تنظیم تخفیف.

اطلاعات این پیش‌نمایش در `localStorage` مرورگر فعلی ذخیره می‌شوند؛ حساب‌های مدیر، نقش‌ها، وضعیت سایت و تأیید سفارش‌ها بین دستگاه‌ها همگام نیستند.

## مهم: موارد لازم برای فروش واقعی
این ZIP یک **پیش‌نمایش فرانت‌اند** است و درگاه پرداخت یا بک‌اند زنده ندارد. پرداخت فعلی فقط سفارش آزمایشی محلی می‌سازد و پولی دریافت نمی‌کند؛ ایمیل واقعی ارسال نمی‌شود و فایل دیجیتال واقعی به شکل امن تحویل داده نمی‌شود. قبل از انتشار عمومی باید موارد زیر به سرور متصل شوند:

- API و پایگاه داده برای کاربران، محصولات، قیمت‌ها، سفارش‌ها و گزارش‌ها
- ورود امن و نقش مدیر در سمت سرور (رمز `2468` فقط برای پیش‌نمایش است و امن نیست)
- آپلود فایل‌ها به فضای خصوصی و لینک دانلود زمان‌دار که فقط پس از تأیید پرداخت از سمت سرور صادر شود
- درگاه پرداخت با کلیدهای محرمانه سمت سرور و بررسی callback/وضعیت تراکنش
- SMTP یا سرویس ایمیل برای رسید سفارش و لینک ورود به کتابخانه خریدها
- اعتبارسنجی فایل، محدودیت حجم، پشتیبان‌گیری، ثبت رخداد و حفاظت در برابر سوءاستفاده

هیچ کلید محرمانه پرداخت یا SMTP را در فایل‌های React یا مرورگر قرار نده.


## امکانات افزوده نسخه ۱.۲
- مدیر می‌تواند برای هر محصول فایل دانلود بارگذاری کند یا هنگام ساخت محصول فایل را انتخاب کند.
- پس از تأیید سفارش آزمایشی توسط مدیر، فایل محصول در کتابخانه آزمایشی نمایش داده می‌شود و در صورت وجود فایل بارگذاری‌شده، لینک دانلود فعال است.
- کنترل باز/بسته بودن فروشگاه در تنظیمات مدیر؛ هنگام بسته بودن پیام «پر قدرت برمی‌گردیم» نمایش داده می‌شود.
- محدودیت فایل نسخه نمایشی: ۲ مگابایت به دلیل ذخیره محلی مرورگر. برای فایل‌های حجیم و کنترل دسترسی واقعی باید بک‌اند و فضای ذخیره‌سازی خصوصی متصل شود.


## مدیریت اطلاعیه‌ها
از پنل مدیریت، بخش «مدیریت اطلاعیه‌ها» را باز کن. می‌توانی عنوان و متن کوتاه اطلاعیه را بسازی، نوع آن را انتخاب کنی، منتشر یا غیرفعال کنی و اطلاعیه‌ها را حذف کنی. اطلاعیه فعال در نوار بالای فروشگاه نمایش داده می‌شود. در این نسخه اطلاعات در مرورگر فعلی ذخیره می‌شوند؛ برای انتشار سراسری روی سایت آنلاین، ذخیره‌سازی سمت سرور لازم است.


## هشدار مهم درباره نسخه آزمایشی
تأیید مدیر در این نسخه فقط وضعیت سفارش آزمایشی را تغییر می‌دهد؛ هیچ پولی دریافت نمی‌شود و این به‌معنی اتصال به درگاه پرداخت نیست. رمزها در مرورگر ذخیره می‌شوند و برای فروش عمومی امن نیستند. برای کارکرد واقعی باید احراز هویت، نقش‌ها، وضعیت باز/بسته، سفارش‌ها و تأیید پرداخت در بک‌اند و پایگاه داده اجرا شوند.


## امکانات نسخه ۱.۶

- پنل تیکت پشتیبانی: کاربر تیکت ارسال می‌کند و مدیر می‌تواند پاسخ دهد یا تیکت را ببندد.
- نظرات و امتیازدهی: نظرات قبل از نمایش عمومی باید توسط مدیر تأیید شوند.
- تیک آبی: مدیر اصلی می‌تواند ایمیل هر کاربر را در بخش «مشتریان و دسترسی‌ها» وارد و تیک آبی را فعال/غیرفعال کند؛ نشان روی نظرهای تأییدشده با همان ایمیل دیده می‌شود. مدیران در پنل نیز نشان آبی دارند.
- نوار اطلاعیه بالای سایت: از بخش «مدیریت اطلاعیه‌ها» قابل انتشار است.
- دکمه‌های شناور فقط برای «تیکت پشتیبانی» و «راهنمای هوشمند» باقی مانده‌اند؛ بخش پیام مستقیم به مدیر حذف شده است.
- چت‌بات راهنما با پاسخ‌های پایه‌ای و دکمه شناور؛ فعال/غیرفعال‌سازی از بخش تنظیمات مدیر.

**محدودیت مهم:** این امکانات در نسخه نمایشی در localStorage مرورگر ذخیره می‌شوند. چت‌بات فعلاً پاسخ‌گوی قاعده‌محور است و به هوش مصنوعی آنلاین وصل نیست. برای اینکه مشتریان و مدیران در دستگاه‌های مختلف به داده‌های مشترک دسترسی داشته باشند، باید سرور، پایگاه داده و احراز هویت امن اضافه شوند.


توجه: در نسخه ۱.۶، تیک آبی بر اساس ایمیل واردشده در مرورگر فعلی ذخیره می‌شود. تا زمانی که سیستم حساب کاربری و بک‌اند اضافه نشود، این نشان احراز هویت واقعی و سراسری نیست.

## انتشار آزمایشی روی GitHub Pages

این پروژه چون فرانت‌اند React/Vite است، می‌تواند برای نمایش آزمایشی روی GitHub Pages منتشر شود:
1. در GitHub یک repository جدید بساز و فایل‌های همین پوشه را در آن بارگذاری کن.
2. در بخش Settings → Pages، منبع انتشار را روی GitHub Actions قرار بده.
3. فایل workflow از قبل در مسیر `.github/workflows/deploy.yml` قرار دارد؛ آن را همراه پروژه به شاخه `main` بفرست.
4. در Settings → Pages، منبع را روی GitHub Actions بگذار. پس از پایان اجرای workflow، لینک سایت در همان صفحه ظاهر می‌شود.

این انتشار فقط برای نمایش و تست رابط است؛ اطلاعاتی که در `localStorage` ذخیره می‌شوند فقط در همان مرورگر و همان دستگاه در دسترس‌اند. تیکت‌ها، نقش‌ها، تأیید سفارش‌ها و وضعیت سایت بین بازدیدکنندگان همگام نمی‌شوند. رمز مدیر داخل کد فرانت‌اند برای انتشار عمومی امن نیست؛ از اطلاعات واقعی یا خصوصی استفاده نکن و قبل از انتشار عمومی، ورود مدیر و داده‌ها را به بک‌اند منتقل کن.


## نسخه ۱.۷ — آماده‌سازی اتصال Supabase

- کتابخانه رسمی `@supabase/supabase-js` اضافه شده است.
- فایل `src/lib/supabase.js` کلاینت Supabase را از متغیرهای محیطی می‌سازد.
- در پنل مدیریت ← تنظیمات سایت، بخش «اتصال پایگاه داده Supabase» برای بررسی تنظیمات و دسترسی به جدول `products` اضافه شده است.
- فایل `.env.example` نمونه متغیرهای لازم را دارد. آن را به `.env` کپی کن و آدرس پروژه و کلید عمومی را در آن قرار بده. فایل `.env` در Git نادیده گرفته می‌شود.

### تنظیم اتصال روی کامپیوتر
1. در پوشه پروژه، فایل `.env.example` را کپی کن و نام کپی را `.env` بگذار.
2. مقدار `VITE_SUPABASE_URL` را با Project URL پروژه خودت جایگزین کن.
3. مقدار `VITE_SUPABASE_PUBLISHABLE_KEY` را با Publishable key جایگزین کن. از Secret key یا service_role استفاده نکن.
4. اجرا کن: `npm install` سپس `npm run dev`.
5. در پنل مدیریت → تنظیمات سایت، روی «بررسی اتصال به Supabase» کلیک کن.

### تنظیم انتشار GitHub Pages
در مخزن GitHub برو به Settings → Secrets and variables → Actions → New repository secret و این دو Secret را بساز: `VITE_SUPABASE_URL` و `VITE_SUPABASE_PUBLISHABLE_KEY`. Workflow هنگام build آن‌ها را دریافت می‌کند.

**محدودیت مهم:** این نسخه فقط کلاینت Supabase و تست اتصال جدول `products` را اضافه می‌کند؛ هنوز محصولات، سفارش‌ها، تیکت‌ها، نظرات، مدیران و وضعیت باز/بسته فروشگاه به‌طور کامل از localStorage به Supabase منتقل نشده‌اند. برای استفاده واقعی، باید مهاجرت داده‌ها، ورود امن Supabase Auth، سیاست‌های RLS متناسب با ساختار دقیق جداول، و عملیات حساس سمت سرور پیاده‌سازی و آزمایش شوند.


## نسخه اصلاح‌شده — حساب کاربری و محدودیت خرید

- ثبت‌نام با نام، نام کاربری، ایمیل و رمز عبور از طریق Supabase Auth اضافه شده است.
- ورود، خروج، بازیابی رمز و حفظ نشست ورود پس از بارگذاری مجدد با Supabase Auth انجام می‌شود.
- افزودن محصول به سبد و ثبت سفارش آزمایشی فقط برای کاربر واردشده فعال است.
- سفارش آزمایشی به شناسه کاربر و ایمیل حساب واردشده متصل می‌شود.
- بخش اطلاعات مدیر در داشبورد اضافه شده است؛ مدیران فرعی می‌توانند نام، نام کاربری و رمز جدید خود را در این نسخه نمایشی تغییر دهند. رمز در رابط کاربری نمایش داده نمی‌شود.

### تنظیم محیط
فایل `.env.example` را به `.env` کپی کن و آدرس پروژه و کلید عمومی (publishable/anon) را وارد کن. هرگز `service_role` یا کلید Secret را در متغیرهای `VITE_` قرار نده.

### محدودیت‌های مهم پیش از انتشار عمومی
این پروژه هنوز نسخه کامل فروشگاه عملیاتی نیست:
- محصولات، مدیران، سفارش‌ها، تیکت‌ها و تنظیمات فعلی همچنان در بخش‌هایی از برنامه از `localStorage` استفاده می‌کنند؛ فقط ورود مشتری به Supabase Auth متصل شده است.
- ورود مدیر فعلی هنوز سامانه نمایشی سمت مرورگر است و تغییرات مدیران فرعی نیز محلی است؛ برای امنیت واقعی باید مدیران و نقش‌ها با جدول‌های امن و RLS در Supabase پیاده‌سازی شوند.
- ثبت سفارش هنوز پرداخت واقعی انجام نمی‌دهد. تا اتصال درگاه و تأیید تراکنش در سمت سرور، هیچ سفارش را پرداخت‌شده یا تحویل امن فایل تلقی نکن.
- برای ساخت حساب، تأیید ایمیل و بازیابی رمز، تنظیمات Auth و URLهای مجاز در داشبورد Supabase را متناسب با دامنه منتشرشده تنظیم کن.
